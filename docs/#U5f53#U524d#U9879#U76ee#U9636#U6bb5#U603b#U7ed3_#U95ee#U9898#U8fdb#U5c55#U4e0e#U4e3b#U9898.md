# 当前项目阶段总结：问题、进展、主题与创新点

本文用于总结 `/remote-home/ming/3dgs-avatar-release-main` 当前阶段已经做过的工作、已经解决和仍未解决的问题，以及当前更适合作为论文主线的主题和创新点。

## 1. 当前建议确立的主题

当前项目最合适的主题，不再只是“做一个可动画的人体 Gaussian Avatar”，而是升级为：

> 一种基于显式绑定的结构化、可解释且可编辑的人体 Avatar 表示，在统一表示中联合建模运动分解、区域语义分解与区域级外观资产。

更具体一点，可以写成：

> 基于显式绑定的语义可分解 Avatar 表示，在统一表示中联合建模运动层级与细粒度人体区域语义，并将这些可解释因子进一步转化为可导出的区域级外观资产，为后续编辑与替换提供基础。

这个主题比单纯“解释性可视化”更强，因为它强调的不是把结果画出来，而是把 Avatar 内部真的做成可分解、可导出、可操作的结构化表示。

## 2. 当前比较成立的创新点

### 2.1 表示层创新

不是把 Gaussian 只看作一堆可渲染点，而是给每个 Gaussian 显式绑定：
- 运动层级信息：`rigid / soft / free`
- 区域语义信息：`body / cloth` 以及进一步细化到 `hair / face / skin / upper / lower / shoes` 等
- 稳定性与细结构线索：`temporal / thin / semantic / body_prob / cloth_prob`

也就是说，当前 Avatar 内部已经不是黑箱场，而是一个带有显式结构解释的表示。

### 2.2 语义资产化创新

不是只输出分割图，而是把区域语义进一步导出成可复用资产：
- `semantic_editable_assets/masks`
- `semantic_editable_assets/raw_masks`
- `semantic_editable_assets/coarse_masks`
- `semantic_editable_assets/compact_head_masks`
- `semantic_editable_assets/motions/*.npz`
- `semantic_editable_assets/preview`
- `semantic_editable_assets/grouped_preview`
- `semantic_editable_assets/parser_preview`
- `semantic_editable_assets/compact_head_preview`

这一步的意义在于：解释结果不只是“看图”，而是变成了可保存、可分析、可继续编辑的中间资产。

### 2.3 从“可解释”走向“可编辑”的路线

当前最有潜力的升级路线是：
- 第一层：显式绑定的运动解释
- 第二层：细粒度语义区域解释
- 第三层：区域级 appearance asset 导出
- 第四层：基于这些资产实现局部替换、局部编辑、局部重着色

也就是说，项目已经从“可解释 Avatar”开始具备走向“可编辑 Avatar”的基础，但还没有完全做完编辑闭环。

## 4. 已经解决或基本解决的问题

### 4.1 Hulk 细粒度标签已经真正接进来了

这件事已经不是概念阶段，而是代码和导出结果都已经打通：
- 可以读 Hulk 结果

- 可以做 compact semantic 映射
- 可以用于训练 supervision

### 4.2 细粒度预览已经比早期版本清楚很多

此前很多版本的问题是：

这些问题大部分已经解决，尤其是 raw preview / compact preview 的检查价值已经明显提升。

之前 `compact_head_preview` 容易让人误以为模型结果很好，但其实第一格是 `source_rgb`，不是模型 render。这个误导点已经被识别并修正。

此前 compact 训练时 fallback KNN 会因为 `torch.cdist` 占用过大导致显存爆掉，这个问题已经被修掉，训练可以正常跑完。

## 5. 当前仍然没有解决的问题

### 5.1 compact6 训练后的主渲染结果明显变坏

这是当前最核心的问题。

虽然 `377_compact6_train_v1` 成功训练完了，指标也不是完全不可看，但实际渲染图明显发黑、发糊、出现异常拖影，和旧的 `377_parsingweak_v1` 相比退化明显。

这说明：
- 问题不在 export 图本身
- 问题主要在训练侧
- compact semantic supervision 当前权重或接入方式过强，正在把原本较稳定的 body/cloth 绑定分布拉坏

也就是说，当前 compact6 的主问题不是“没读到 Hulk”，而是“compact 监督把主重建伤到了”。

### 5.2 old good checkpoint 与 current compact export 之间还有代码兼容问题

在拿旧的 `377_parsingweak_v1` checkpoint 做新的 compact 资产导出时，暴露出 `render.py` 里 `appearance_compact` / `_masked_region_stats()` 的 mask 维度兼容问题。

这个问题说明：
- 当前 compact export 对新模型路径已经基本能跑
- 但对旧 checkpoint 的兼容性还没有完全补齐

### 5.3 Hulk 多视角对齐问题还没有真正解决

当前最稳定、最可信的是 `cam1` 路线。

多视角还存在的问题是：
- Hulk 输出文件与本项目数据命名/帧索引/视角组织方式不完全一致
- 经过转化后，某些视角的标签和训练/渲染读取并没有完全对齐
- 因此 full multi-view 直接上会把分割质量拉低

所以现在更稳妥的策略仍然是：
- 先把 `cam1` 路线做稳
- 再处理 multi-view 对齐

### 5.4 `layer / thin / semantic` 等解释图还不够论文终版

当前这些图已经有检查价值，但还有明显问题：
- `layer` 仍然偏 heuristic，可读性不够稳定
- `thin` 还达不到“精确识别鞋带/裤带/小配件”的程度
- `semantic` 的视觉表达还不够强

所以这部分目前更适合叫“解释性 probe / 分析图”，还不适合作为最终论文主打定量模块。

### 5.5 真正的“可编辑”闭环还没做完

当前做到了：
- 结构化表示
- 细粒度语义导出
- 区域级资产导出

但还没有完全做完：
- 区域 appearance code 的独立存储与替换
- 区域级属性替换接口
- 跨主体的语义资产迁移
- 真正可控的“点一下肤色/发色/上衣区域就能替换”的编辑系统

因此现在更准确的说法是：

> 已经完成“可解释、可资产化”的主体框架，正在向“可编辑”推进，但编辑闭环还未完成。

## 7. 当前建议的最务实主线

当前最务实的路线不是继续同时推很多方向，而是按下面顺序：

1. 先保住旧 checkpoint 的主渲染质量
2. 让旧 checkpoint 也能稳定导出当前的 Hulk compact 资产
3. 在不伤主渲染的前提下，做一版保守 compact finetune
4. 等 compact 训练稳定后，再推进 appearance asset 替换
5. 最后再做跨主体替换和真正的编辑 demo

## 8. 当前已经做的一个关键判断

### 11.3 多视角训练的 OOM 根因已经定位并修复

此前多视角 Route A 训练会在初始化阶段直接 OOM，不是训练过程中慢慢炸显存，而是一开始就进不了优化。

根因是：

- 多视角数据集仍然用了 `preload: true`
- 数据集初始化时会一次性构造全部 `Camera`
- `Camera` 构造时又立刻把图像和 mask 搬到 CUDA

已经完成的修复：

- 将
  `/remote-home/ming/3dgs-avatar-release-main/configs/dataset/zjumocap_377_multiview_cam1sem.yaml`
  改为 `preload: false`
- 并在
  `/remote-home/ming/3dgs-avatar-release-main/tools/run_377_multiview_direct_hulk_finetune.py`
  中强制传入 `dataset.preload=false`

修复后，多视角训练已经能完整跑完。

### 11.5 “render 和真实图不一样”这一点已经重新定位

之前看渲染图时，一个很强的表面现象是：

- render 是黑背景人像
- 原始 JPG 是摄影棚背景

本轮已经确认，这不是 render 分支单独坏掉，而是训练数据读取时就把前景外区域抠成了黑色。

关键逻辑在：

- `/remote-home/ming/3dgs-avatar-release-main/dataset/zjumocap.py`

其中：

- `image[~mask] = 255. if self.white_bg else 0.`

而当前配置：

- `/remote-home/ming/3dgs-avatar-release-main/configs/dataset/zjumocap_377_multiview_cam1sem.yaml`
- `white_background: false`

所以现在的正确理解是：

- render 与训练/评估管线里的 `masked gt` 是对齐的
- render 与原始摄影棚 JPG 差异大，主要是背景域约定不同
- 当前真正需要修的不是背景，而是人体前景本体的清晰度

### 11.7 “前景发糊”的根因已经重新定位

这一轮最重要的结论之一是：

当前前景偏糊，不是单纯因为 Hulk 标签接错了，也不是因为 render 分支单独坏了，而是训练配置本身过于保守。

当前主拖后腿的顺序大致是：

1. 高斯密度被冻结，细几何长不出来
2. 纹理头 `shallow_mlp` 表达能力偏弱
3. 前景 mask 监督偏软
4. Hulk 语义分支不是当前“发糊”的第一主因

更具体地说：

- 这次多视角训练是从旧 checkpoint 继续微调的
- 并且在 option 中完全禁掉了 redensify
- 当前使用的纹理头仍然是较浅的 `shallow_mlp`
- 主图像监督以 `L1 + 小权重 perceptual + L1 mask` 为主，边界不够硬

因此会出现：

- 大轮廓还在
- 但手、脚、鞋子、四肢边缘和衣物局部细节明显发糊

### 11.10 `sharp_v1 / sharp_v2` 两轮清晰度修复实验结果

在确认“前景偏糊”的主要问题来自高斯密度、浅纹理头和偏软的前景监督之后，本轮继续做了两次针对清晰度的续训修复：

- `sharp_v1`：
  `/remote-home/ming/3dgs-avatar-release-main/exp/fixedv2/377_multiview_direct_hulk_sharp_v1`
- `sharp_v2`：
  `/remote-home/ming/3dgs-avatar-release-main/exp/fixedv2/377_multiview_direct_hulk_sharp_v2`

两轮实验的出发点都是：

- 从当前主线最好模型 `377_multiview_direct_hulk_v2/best_ckpt.pth` 出发
- 通过续训方式修复前景模糊
- 不破坏已经建立起来的多视角 direct Hulk 语义对应关系

#### `sharp_v1` 的做法

`sharp_v1` 采取的是较强干预：

- 打开一段安全 redensify
- `mask_loss_type` 改为 `bce`
- 增大 `lambda_mask`
- 增大 `lambda_perceptual`
- 新增 `lambda_dssim`

结果：

- `PSNR = 32.4877`
- `FG_PSNR = 20.8463`
- `FG_LPIPS = 0.1733`

对比主模型 `v2 best`：

- 主模型 `v2 best` 为：
  - `PSNR = 32.7703`
  - `FG_PSNR = 21.1016`
  - `FG_LPIPS = 0.1398`

结论：

- `sharp_v1` 没有把前景修清楚
- 指标与视觉都没有超过 `v2 best`
- 并且局部外观更容易被扰脏

#### `sharp_v2` 的做法

`sharp_v2` 是在 `sharp_v1` 失败后做的更保守版本：

- 撤掉 `lambda_dssim`
- `mask_loss_type` 回退到 `l1`
- `lambda_mask` 回到更稳的值
- 只保留更短、更保守的 redensify 窗口
- 进一步压低续训阶段的 parser / compact semantic 干扰

结果：

- `PSNR = 32.6373`
- `FG_PSNR = 20.8932`
- `FG_LPIPS = 0.1431`

和 `sharp_v1` 相比：

- `sharp_v2` 明显更稳
- 副作用比 `sharp_v1` 小
- `FG_LPIPS` 明显优于 `sharp_v1`

但和 `v2 best` 相比：

- 仍然没有超过 `FG_PSNR = 21.1016`
- 也没有超过 `FG_LPIPS = 0.1398`

结论：

- `sharp_v2` 证明更保守的修法比 `sharp_v1` 更合理
- 但它依然没有成为新的主模型
- 当前主线最优 checkpoint 仍然是：
  `/remote-home/ming/3dgs-avatar-release-main/exp/fixedv2/377_multiview_direct_hulk_v2/best_ckpt.pth`

### 11.11 对“续训修补当前 best checkpoint”这条路线的最新判断

经过 `sharp_v1 / sharp_v2` 这两轮实验，当前可以下一个更明确的工程判断：

- 不是 Hulk 语义标签本身把模型彻底拖坏了
- 也不是“多视角 + direct parser”这条路线完全不成立
- 真正的问题在于：
  **从当前 `v2 best` checkpoint 出发继续做 redensify / sharpen 类续训，收益很有限，而且很容易越训越坏。**

从日志看，`sharp_v1` 和 `sharp_v2` 的 best 都出现在 very early stage，之后会快速退化。这说明：

- 当前 `v2 best` 本身已经非常接近它这条参数轨迹下的局部最优
- 再用后处理式续训去“补清晰度”，边际收益很低
- 一旦继续往下训，容易把原先较稳定的外观和前景质量破坏掉

因此，这一轮修复之后，当前更合理的策略不是继续对同一个 checkpoint 做强行修补，而是：

1. 保留 `v2 best` 作为当前主模型
2. 不再把 `sharp_v1 / sharp_v2` 作为主模型替换掉它
3. 后续把重点转向“训练配方本身的重构”，而不是继续给这个 checkpoint 打补丁

换句话说，当前最应该做的是：

- 改主训练配方
- 而不是继续修补当前 best checkpoint

这也意味着，下一阶段真正值得推进的，不再是：

- 再做一轮更激进的 `sharp_v3`

而更应该是：

- 在新的主训练配方里重新考虑纹理头能力、densify 策略、语义监督介入时机与强度
- 让“主训练过程本身”就生成更清楚的人体，而不是依赖后期抢救

### 11.12 当前确认后的“两阶段训练”新主线

在继续分析了当前代码、数据读取链路和多轮实验结果之后，新的更合理主线已经明确，不再继续围绕旧的 `v2 best` 做补丁式续训，而是切成两个阶段：

#### Stage A：高分辨率主重建

目标：

- 先把人物主渲染尽可能训清楚
- 先恢复脸部和细节区域的像素表达能力
- 先让几何密度和纹理能力在主训练阶段自然长出来

当前已经落地的配置方向：

- 数据集：`zjumocap_377_multiview_hq`
- 训练视角：`1..20`
- 验证视角：`21,22,23`
- 训练分辨率：`768 x 768`
- 重采样：`lanczos=true`
- `texture=mlp`
- 从头训练
- `dataset.parsing_prior.enable=false`
- `dataset.preload=false`

- 当前模糊的根因不是“数据不够”，而是 `1024 -> 512` 后脸部像素预算太低
- `shallow_mlp` 容量偏弱
- 从旧 checkpoint 做 resume-safe 续训时，densify 被抑制，几何和纹理都难以真正补回来

#### Stage B：轻量 direct Hulk 语义微调

目标：

- 在 Stage A 已经较清楚的人体重建上，再把 Hulk 细粒度标签压进去

- parser / compact semantic 权重明显下调
- Stage B 不再 redensify
- 只做轻量语义 finetune

#### 当前代码侧已经确认的关键点

- 新增配置文件已经通过 Hydra 配置级检查，可以正确合并：
  - `configs/dataset/zjumocap_377_multiview_hq.yaml`

#### 当前阶段结论

因此，接下来不再建议：

### 11.14 这一轮真正定位出的根因

这次继续向下排查之后，已经把问题从“训练现象”定位到了“数据读取与监督像素分配方式”：

#### 旧版确实使用了 ZJU 的 `png mask`，但用法太浅

例如：

- `/remote-home/ming/3dgs-avatar-release-main/data/ZJUMoCap/CoreView_377/1/000000.png`

这类 `png mask` 在旧版流程里并不是没用，而是：

1. 读取 `jpg` 与对应 `png mask`
2. 对图像和 mask 做去畸变
3. 把整张 `1024 x 1024` 图片直接缩放到训练分辨率（此前是 `512`，现在 Stage A 是 `768`）
4. 仅仅用 mask 把背景置黑

也就是说，旧版流程中：

- `png mask` 只被用于“去背景”
- 没有被用于“先按人体区域裁切，再放大到训练分辨率”

这就带来一个核心问题：

- 虽然背景被抠掉了
- 但整张图依旧保留了大量无效黑背景区域
- 训练分辨率中的有效人体像素占比仍然偏低
- 脸、手、鞋等细节区域分到的像素预算仍然太少

因此，上一轮 Stage A 即便已经提升到 `768 x 768`，本质上仍然属于“全图缩放训练”，所以细节依然不够清楚。

#### 当前已确认的更准确结论

当前更深层的问题不是：

- 数据集不够
- Hulk 标签不够细
- 语义监督直接拖坏了主渲染

而是：

- 人体在输入图像中的有效面积不够大
- 训练时把太多分辨率浪费在了无效背景上
- 导致前景细节监督密度不足

## 10. 最近新增的重要阶段判断

### 10.1 当前已经确认：主重建必须先站稳，不能继续把所有约束一次性压进训练

最近这一轮最大的变化，不是又多做了一版 Hulk，而是把一个关键判断彻底做实了：

**如果主重建本身还不稳定，就不能继续把多视角 Hulk、crop、更强语义监督、更多导出约束同时压进训练。**

原因已经在实验里反复被验证：

- 更激进的 `crop` 路线虽然一开始看起来更像“提高前景像素预算”，但实际训练中更容易把高斯拓扑与 opacity dynamics 推向错误解。
- 后续即使把工程性崩溃修掉，模型也会塌成接近透明的结果，最终 render 全黑。
- 这说明当前阶段的主矛盾不是“Hulk 标签没有接进来”，而是“主重建还没有站稳，导致后续语义监督没有正确底座”。

因此，当前阶段的策略已经从：

- 直接把多视角 Hulk + crop + 显式绑定 + 可解释 + 可编辑资产一起推

调整为：

1. 先稳定主重建。
2. 再提清晰度。
3. 再把 Hulk 语义监督轻量接回。
4. 最后继续推进 interpretability 与 editable assets。

### 12.1 新结论：当前问题不只是锐化不够，而是训练范式本身还不对

这轮对比之后，已经可以确认：

- `sharp_v1` 没有明显优于上一版 `mono_v1`
- 它只是在个别视角上让轮廓略紧一点
- 但脸部、肩膀、鞋子、边界等关键区域并没有真正变清楚
- 与 GT 相比，缺失的主要仍然是高频纹理和跨视角一致细节

指标也支持这个结论：

- `mono_v1`: `PSNR 30.7498 / FG_PSNR 19.9192 / FG_LPIPS 0.1459`
- `sharp_v1`: `PSNR 30.6756 / FG_PSNR 19.5546 / FG_LPIPS 0.1766`

也就是说，当前 `sharp finetune` 不是新的主线终点。

### 12.2 这轮真正定位出的根因

当前“渲染还能看出人，但就是不够清楚”的核心原因，已经比之前更明确：

#### 根因 A：当前稳定底座本质上是单视角 base

当前最稳定的 Stage A 配置是：

- `dataset=zjumocap_377_mono`
- `train_views=['1']`
- `val/test` 仍然评估 `2~23`

这意味着：

- 训练时只见过 `view 1`
- 但我们实际在看的很多渲染图，是 `c02~c23` 的未见视角
- 因此现在的糊，里面本来就包含了明显的 novel-view 泛化误差

所以，当前最稳定这版的真实定位应当是：

- 它证明了 `explicit_binding + full image + 原 mask + no Hulk` 可以稳定重建出人
- 但它并没有证明“新视角高质量重建”已经成立

#### 根因 B：从 `512` checkpoint 往 `768` 做 finetune，无法凭空补出没学到的细节

`sharp_v1` 的路线是：

- 先用 `512x512` 单视角得到 `mono_v1`
- 再切到 `768x768` 做保守 finetune

这条路线本质上只能做“轻微修补”，不能解决：

- 低分辨率起点导致的细节缺失
- 单视角起点导致的跨视角结构缺失

#### 根因 C：当前 sharp 调整偏 regularization，不是表示能力层面的升级

当前 sharp 路线主要调的是：

- `dssim`
- `perceptual`
- `mask`
- `aiap`
- 短窗口 redensify

但没有从根上改变：

- 训练视角数量
- Stage A 的几何信息覆盖
- 纹理分支容量与高频表达来源

所以继续在 `sharp_v1` 上小修小补，收益会越来越有限。

### 12.3 对当前主线的影响

这次判断对整个项目主线其实是有帮助的，因为它把“哪里该先做”重新理顺了。

当前更合理的阶段划分应该是：

#### Stage A1：单视角稳定 base

用途：

- 验证显式绑定主线可行
- 验证 full image + 原 mask + no Hulk 这条线稳定
- 给后续代码调试提供 sanity baseline

当前对应实验：

- `/remote-home/ming/3dgs-avatar-release-main/exp/stageA/377_baseline_explicit_mono_v1`

#### Stage A2：真正的多视角 RGB 重建 base

这是接下来更应该投入的主线。

其目标不是语义，而是：

- 先把多视角几何和外观重建站稳
- 让 novel-view 本身先渲清楚
- 给后面的 Hulk 语义监督提供一个不会拖垮主重建的底座

这一步应坚持：

- 多视角 RGB
- full image
- 原始 PNG mask
- 不开 crop
- 不开 Hulk 监督
- 保留 `explicit_binding`

#### Stage B：轻量 Hulk finetune

顺序应当改成：

1. 先有清楚的多视角 RGB base
2. 再轻量接回 Hulk
3. 验证不伤主渲染的前提下，提升 body/cloth / compact semantic 的可分性

#### Stage C：interpretability 与 editable assets

只有在 Stage B 稳住之后，后面的：

- semantic assets
- interpretability
- editable assets

才真正有高质量落地基础。

### 12.4 当前最务实的建议

因此，当前不建议继续把时间主要花在：

- 反复小修 `sharp_v1`
- 在单视角底座上继续叠 Hulk
- 把单视角 novel-view 结果当成最终质量判断标准

当前最值得做的，是：

1. 把单视角 `mono_v1` 保留为稳定 sanity base
2. 正式切到“多视角 RGB、无 Hulk、无 crop”的 Stage A2
3. 尽量从 HQ 分辨率从头训练，而不是继续做 `512 -> 768` 补丁式 finetune
4. 等多视角 base 清楚后，再把 Hulk 以轻量方式接回

这条路线最符合当前项目的主题推进方式：

> 先建立稳定、清楚的结构化 Avatar 重建底座，再在这个底座上叠加语义可分解、解释输出和最终可编辑资产。
