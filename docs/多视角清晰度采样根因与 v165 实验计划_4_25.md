# 多视角清晰度采样根因与 v165 实验计划

日期：2026-04-25

## 当前结论

v164b 验证了显式绑定路线是可行的，但还没有解决清晰度根因。

v164b best 出现在 1500：

```text

L1_fg    = 0.048948
SSIM_fg  = 0.852758
```

它明显优于 v160a、v163c、v158a：

```text
v158a FG_LPIPS 0.168829
v160a FG_LPIPS 0.166306
v163c FG_LPIPS 0.170153
v164b FG_LPIPS 0.160253
```

但仍然明显弱于 v142e 和 mono baseline：

```text
v142e train FG_LPIPS    0.139722
baseline render LPIPS   0.021162
v142e render LPIPS      0.023021
v164b render LPIPS      0.025965
```

机制日志说明：v164b 的几何硬化开关已经打开，但 hardest contour 没有真正被 boundary/head 强接管。

```text
support          ~= 0.916
owner_takeover   ~= 0.36 - 0.53
boundary_takeover~= 0.02 - 0.04
boundary_focus   ~= 0.01 - 0.03
sharpen_gate     ~= 0.99
```

所以它不是“显式绑定失败”，而是“显式绑定能稳定出完整人，但多视角监督仍把边界和高频平均软了”。

## 三个主因

### 1. 多视角采样稀释 / 训练不够

当前训练集约为：

```text
570 frames * 20 train cameras = 11400 samples
```

旧的随机采样逻辑每个 iteration 只取一个 camera-frame：

```python
data_stack = list(range(len(scene.train_dataset)))
data_idx = data_stack.pop(randint(0, len(data_stack)-1))
data = scene.train_dataset[data_idx]
```

因此 15k iterations 的真实样本曝光约为：

```text
15000 / 11400 = 1.32 次 / 样本
```

即使累计到约 24k render exposure，也只有：

```text
24000 / 11400 = 2.1 次 / 样本
```

这和 mono 15k 的约 26 次 / 样本不是一个训练密度。多视角下人能出来，但手臂、腰侧、衣服褶皱、脸部、鞋边等高频区域没有被充分拟合。

### 2. SMPL / 相机小对齐误差 + 显式绑定偏软

前面抽查过，整体对齐合理，但 768 分辨率下仍有约 5-16px 的局部中心偏差。这个量级足够把边界、手臂、腰侧和衣服褶皱平均掉。

v164b 的 sharpen gate 已开，但 boundary takeover 很低，说明几何硬化开始工作，hardest contour 仍没有足够强的、稳定的梯度接管。

### 3. 多视角颜色 / 曝光不一致

20 个训练相机亮度、白平衡、颜色质量不同。统一 texture MLP 会倾向解释平均颜色，质量差或偏色视角抽得太多时，会进一步压低纹理高频。

## 方案判断

直接把每个样本训练到 25 次需要：

```text
11400 * 25 = 285000 render exposure
```

如果使用 K=4 multi-view gradient accumulation：

```text
285000 / 4 = 71250 optimizer steps
```

这在当前 3 秒左右 / render 的成本下太重，不适合作为第一步。

更合理的路线是分阶段验证：

```text
v165: frame-balanced + camera-quality weighted, K=1
v166: same-frame K=2 gradient accumulation
v167: same-frame K=4 late finetune
```

v165 的目的不是一次性达到 baseline，而是先验证“采样根因”是否成立。它保持每步一个 render/backward，成本和现有训练一致。

## v165 采样策略

v165 使用：

```text
先均匀/轮转抽 frame
再在该 frame 内按 camera quality weight 抽 camera
每个 camera 设置 min_prob / max_prob，避免低权重相机被饿死
```

这样既让优质相机提供更多清晰监督，又不完全牺牲相机 20 等接近 held-out view 的泛化视角。

## 预期

v165 可改善：

```text
多视角采样稀释
高质量视角曝光不足
低质量相机拖平均
部分边界/纹理梯度不稳定
```

v165 不能彻底解决：

```text
SMPL/相机局部错位
严重颜色/曝光差异
boundary head 接管不足
```

如果 v165 有明显收益，再进入 K=2/K=4 same-frame gradient accumulation。否则不应继续在 K accumulation 上耗算力，应优先做 per-camera color/exposure correction 或对齐误差建模。

## 2026-04-26 补记：v165 之后的实验结果

### v165 结果：采样方向有弱信号，但不能作为主线继续堆

v165 使用 `frame_balanced_camera_weighted`，从 v164b best 继续训练。best 出现在 1000：

```text

  L1_fg    = 0.050364

```

继续训练没有带来稳定收益：

```text
v165 @2000 FG_LPIPS = 0.165815
v165 @3000 FG_LPIPS = 0.169767
```

机制上，v165 的 owner 输出和 sharpen gate 都打开了，但 hardest contour 没有真正被强力接管：

```text
iter=3000
support           = 0.9172
owner_takeover    = 0.6458
boundary_focus    = 0.0193
boundary_takeover = 0.0330
boundary_color    = 0.00961
sharpen_gate_mean = 0.992890
```

结论：

```text
frame-balanced + camera-quality weighted 证明“采样稀释”是因素之一，
但它不是当前最主要瓶颈。

v165 只能把 v164b 从 0.160253 小幅推到 0.159906，
且后续训练迅速变差，说明继续堆 K=2/K=4 accumulation 的性价比不高。

当前更关键的问题仍是：
  1. boundary/head 接管不足；
  2. trunk/HF/contour 残差没有稳定进入主输出；
  3. 多视角对齐/光照误差仍会把边界平均软。
```

因此 v165 之后没有继续走“大算力 accumulation 主线”，而是转向更直接的清晰度瓶颈排查。

机制观察：

```text
v166c 能恢复，是因为它基本回到保守 continuation；
这说明光照校正方向不是完全错误，但不适合作为当前阶段的主药。
必须先让主干输出高频/轮廓残差有足够幅度，再考虑 per-camera correction。
```

### 采样结论更新

原始判断里，“多视角采样稀释 / 训练不够”是第一主因。v165-v166 之后需要修正为：

```text
采样稀释是必要修复项，但不是单独足以逼近 baseline 的根因。

当模型主路径本身不能输出足够高频/硬边界时，
更均衡或更高质量的采样只会给它更好的监督，
但不会自动让软输出头变成硬输出头。

所以采样策略保留为辅助配置：
  frame-balanced camera weighted 可以继续用于后续长训；
  但下一主线必须修 trunk/HF/contour 输出幅度与路由。
```

## 当前总判断

截至 v171a 启动后，路线判断更新为：

```text
1. 采样稀释是真问题，但 v165 证明单独修采样只能带来弱收益。
2. photometric / uncertainty 不能在软主路径之前先上，v166 已验证会恶化。
3. v142e / v168a / v170e 说明显式绑定可以做到 0.139 附近。
4. 距离 baseline 的主要差距不是“人不完整”，而是高频和边界硬度不足。
5. 当前最高价值修复是让 trunk/HF/boundary/contour 残差在主输出里有真实幅度，同时保持 selective gate。
```

后续不应再回到“单纯加权、单纯加步数、单纯调 boundary tag”的小修小补。判断一版是否值得长训，应同时满足：

```text
指标:
  FG_LPIPS 明显低于 v170e 0.139228；
  L1_fg 不明显劣化，最好接近或低于 0.0428；
  SSIM_fg 不低于 0.881 附近。

机制:
  boundary_focus 保持 0.08 - 0.10；
  boundary_takeover 不只是 0.10 的路由数字，而是 boundary_color / head_color 有真实输出幅度；
  gate 不全开，不把整个人洗平；
  trunk/HF/head 输出残差不能长期停在接近 0 的幅度。

视觉:
  c22_f000210 / c22_f000240 的手臂边界、肩膀、腰侧、衣服褶皱、鞋边必须肉眼比 v142e/v170e 更硬；
  不能新增鼓包、腰侧外扩、手臂边界漂移。
```

### v181b：受限 view-conditioned texture residual

目的：


```text

约束:

  强 L2 / TV / sparsity 正则
  只在 foreground detail mask 内起作用
  不作用于背景
  不训练 geometry / opacity / scaling
  不改变 canonical base texture 的主体表达
```

关键原则：


### v183：从单一 shared texture 改成“冲突分解”的表示

方向：

```text

  负责稳定、跨视角一致的主体颜色和低频结构。

  负责可共享的高频细节；
  采用 per-surface / per-anchor 显式高分辨率 detail 表示；

  只吸收不可共享的视角相关小残差；
  不能使用大 camera-id MLP 记忆相机；
  以 normal-view relation / visibility / grazing angle 为输入；

semantic layered boundary:
  cloth / skin / hair / shoes 建立独立 boundary ownership；

```

关键变化：

```text
从“一个 canonical texture 解释所有相机”
变成“base / detail / view residual / semantic layer 分工解释”。
```

这才是清晰度上限提升，不是局部调参。

### v184：鲁棒多视角 teacher-student，而不是平均所有视角

当前多视角训练默认把所有相机监督混在一起。
如果某些相机/角度在某些部位更清晰，平均训练会抹掉它。

方向：

```text
1. 为每个 surface anchor / semantic part 估计 view reliability；
2. 对每个部位选择最可靠的 camera/frame 作为 teacher signal；
3. 用 robust aggregation / median / trimmed mean 生成 canonical detail target；
4. student base texture 学可共享细节；
5. residual branch 只学 teacher 无法统一的剩余。
```

这相当于把训练从：

```text
所有视角同权平均
```

改成：

```text
按 surface / semantic / visibility 选择可靠监督，再蒸馏到共享表示
```

预期收益：

```text
衣服褶皱、鞋边、手臂边缘、头发轮廓不会再被低质量视角一起平均掉。
```

```text
5. 加一个 no-op 模块或极短 no-op resume，不允许指标明显退化。
```

验收标准：

```text
如果 v182a 不通过，所有 v182b/v183/v184 都先不要跑。
因为这时任何收益/退化都可能是配置结构错配造成的。
```

#### v182b：alignment diagnostic + calibration

目标：

```text
把“alignment-aware mask 发现错位”升级成“camera/pose residual 真正修正错位”。
```

先做诊断：

```text
统计每个 camera / frame / body part 的 silhouette distance、edge residual、foreground contour error；
重点看 shoulder、arm、waist、hairline、shoe edge；
输出 hardest camera-part-frame 排名。
```

再做校准：

```text
freeze texture / gaussian feature / opacity / scaling；
只训练 per-camera extrinsic residual、intrinsic small residual、per-frame root/pose small residual；
loss 以 mask edge distance、silhouette IoU、image gradient alignment 为主；
输出 corrected alignment cache。
```

验收标准：

```text
v179c best 在 corrected alignment 下，contour/edge residual 必须下降；
如果只是 RGB 指标波动但 contour residual 不降，v182b 不算成功。
```

#### v182c：corrected alignment 上的 texture/detail retrain

目标：

```text
在对齐修正后，验证 high-frequency texture 是否能恢复被平均掉的边界和细节。
```

训练约束：

```text
start = v179c best + corrected alignment cache；
freeze geometry / opacity / scaling；
train texture / detail_high_freq / structured trunk；
保留 K6 + camera-quality + tight photo；
不加新的大 loss 项。
```

验收标准：

```text
FG_LPIPS 必须超过 v179c；
quick masked L1 不得高于 v179c；
肩膀、手臂、腰侧、鞋边、衣服褶皱至少有一组稳定更清晰。
```

#### v183：representation split

触发条件：

```text
v182b 证明对齐修正不足，或 v182c 只能小幅改善但仍明显发糊。
```

实验内容：

```text
shared base texture：负责低频一致性；
explicit detail atlas / surface grid：负责可共享高频；
small view-conditioned residual：负责不可共享视角差异；
semantic boundary layer：负责 cloth/skin/hair/shoe 的边界归属。
```

验收标准：

```text
不能只看全图 PSNR；
必须看 foreground LPIPS、masked L1、hard contour crop、跨视角一致性；
view residual 不能变成 camera-id 记忆器。
```

#### v184：reliable-view teacher-student

触发条件：

```text
v183 后仍存在多视角平均导致的细节变软。
```

实验内容：

```text
为每个 surface anchor / semantic part 估计 view reliability；
选最可靠视角作为 teacher；
用 robust aggregation 生成 canonical detail target；
student 学共享 detail；
residual 只学 teacher 无法统一的部分。
```

验收标准：

```text
衣服褶皱、鞋边、头发轮廓、手臂边界必须比 v179c 更硬；
同时不能引入明显 view flicker 或 camera-specific color shift。
```

## 2026-05-08 根因重判：为什么清晰度一直卡住

结合 v165-v183 和当前代码逻辑，清晰度卡住不是单一参数问题，而是三个层面的结构性冲突叠加。

### 根因 1：当前模型仍在用单一 canonical 主输出平均多视角冲突

当前 texture 路径虽然已经有：

```text
structured trunk
detail_high_frequency
luma branch
face/local carrier
owner head
boundary head
camera affine
camera geometry
```

但核心输出仍是：

```text
同一组 canonical gaussian / texture feature
解释 20 个 train cameras 的颜色、曝光、边界位置和局部高频。
```

多视角数据里实际存在：

```text
相机颜色/曝光/白平衡差异；
局部 camera / SMPL / pose 对齐误差；
mask 边界误差；
训练相机质量差异；
view-dependent 细节和遮挡差异。
```

当这些差异进入同一个 shared texture 输出时，最稳定的优化解就是：

```text
低频对齐；
边界变软；
高频幅度降低；
hard contour 被平均；
衣服褶皱、肩膀、手臂、头发、鞋边不够锐。
```

v175-v179 能提升，是因为它们增强了 HF source 并提高同帧多视角监督密度；
但到 v179c 后收益变窄，说明 shared canonical 表示已经接近当前能承载的上限。

### 根因 2：boundary/head 路由命中了，但输出幅度长期接近零

多轮日志都显示 hardest contour 不再是完全找不到：

```text
boundary_focus    ~= 0.080
boundary_takeover ~= 0.048
owner_takeover    ~= 0.64 - 0.65
support           ~= 0.96
```

但真正画到最终颜色里的 boundary 输出仍很小：

```text
v183b typical:
  boundary_color ~= 0.0006 - 0.0012
  boundary       ~= 0.0002 - 0.0005
  hf_scale       = 0.240
  luma           ~= 0.021 - 0.024
  tiny           ~= 0.015 - 0.022
```

这说明：

```text
系统已经能把点标成 boundary / hard subset；
但 boundary branch 没有足够可信的高频目标，也没有足够自由度/幅度去画硬边界；
继续提高 boundary loss 或 topk_ratio，只会改变路由数字，不会自然产生硬边界颜色。
```

v173/v174/v180/v183 都支持这个结论：

```text
继续拧 boundary/head 不是主突破口。
```

### 根因 3：alignment 误差是真问题，但现在的修法只在监督侧或低自由度残差侧打补丁

v180：

```text
alignment-aware mask 确实命中 hardest contour，
但没有带来肉眼清晰度突破。
```

v183b：

```text
tiny camera geometry residual 让 contour 指标小幅改善，
但 foreground LPIPS 和视觉清晰度没有改善。
```

原因是：

```text
loss mask / uncertainty / tiny camera residual 只是在当前表示上重新分配梯度；
它没有重建相机/人体/轮廓的一致几何；
也没有把不可共享的多视角细节从 shared canonical texture 中分离出去。
```

更重要的是：

```text
per-camera residual 只对训练相机有效；
如果目标是 held-out view 清晰度，它不会自动泛化。
真正需要的是一个能影响所有视角的数据/几何层修复，
或者一个能在新视角也合理工作的 view-conflict 表示。
```

### 根因 4：当前实验曾被 metric substrate 和 config substrate 干扰

v181a 暴露：

```text
option stack 近似 v179c 会丢真实 texture/HF/structured trunk 模块；
partial load unexpected keys 会让实验不再是严格从 v179c 续训。
```

v183a 暴露：

```text
历史 v179c saved best_test_metrics 与当前 validation 指标不完全等价；
必须建立 current-code no-op baseline。
```

因此以后判断实验必须满足：

```text
1. 从真实 .hydra/config.yaml 继承；
2. 先跑 current-code no-op baseline；
3. 同时看 foreground metrics、quick render、contour diagnostic 和 hard crop；
4. 不再用旧 best_test_metrics 单独做 gate。
```

否则会继续产生“方法失败/成功”的假判断。

## 2026-05-08 下一阶段：不要再小修，进入三条大修路线

下一阶段不要再做：

```text
texture_lr 小调；
camera_affine_lr 小调；
boundary loss 小调；
mask width / topk_ratio 小调；
再拉长 v179c / v182c texture-only 训练；
只训练 tiny camera residual。
```

真正应该做的是把“多视角冲突”从 shared canonical texture 里拆出来。

### 大修路线 A：离线 alignment / calibration substrate，而不是 loss mask

目标：

```text
在训练前建立 corrected alignment substrate，
不要只在 train loop 里临时给 loss mask 降权。
```

做法：

```text
1. 用 v179c / v183 diagnostic 找 hardest camera-frame：
   c21/c22/c23 的 edge_symmetric_dist_px 高样本；
   shoulder / arm / waist / hairline。

2. 离线优化一个低维 alignment cache：
   per-camera small SE(3) / 2D residual；
   可选 per-frame root / SMPL global orient residual；
   用 silhouette edge distance、mask IoU、foreground boundary L1 做目标。

3. 输出 corrected camera/pose/mask cache：
   不在 texture train loop 里边训边改；
   先把几何/边界监督变成稳定输入。

4. 在 corrected substrate 上从 v179c 重新训练 HF/source 或 representation split。
```

关键区别：

```text
v180/v183b 是监督侧或低自由度补丁；
路线 A 是数据/几何 substrate 重建。
```

验收：

```text
current-code no-op baseline 不变；
corrected render contour:
  mean_edge_symmetric_dist_px 至少下降 0.3 - 0.5 px；
  hardest 10 samples 明显下降；
  foreground LPIPS 不应恶化。
```

如果离线 calibration 只能带来 0.05 - 0.10 px 的小变化，就不要继续；
说明最大瓶颈不是几何 substrate，而是表示/监督冲突。

### 大修路线 B：representation split，把不可共享多视角差异从 canonical texture 分离出去

目标：

```text
不是再给 shared texture 加一点 residual，
而是明确拆成：
  shared canonical base
  view/camera conflict residual
  robust gate / regularizer
```

建议结构：

```text
base branch:
  继承 v179c shared canonical texture；
  保持主体颜色和大结构。

residual branch:
  low-rank camera/view embedding；
  输入 view direction / camera group / region feature；
  输出小幅 RGB residual 或 HF residual；
  amplitude cap 分 region 控制，例如 0.015 - 0.035；
  不允许改 opacity/scaling/geometry。

gate:
  只在 foreground detail / cloth / skin high-error region 开；
  boundary 区域单独限制，防止漏色；
  test view 用 camera-independent view direction 分支，不直接依赖训练 camera id。

regularization:
  residual L2；
  view consistency；
  leave-one-camera validation；
  residual sparsity / smoothness。
```

这条路线要解决的是：

```text
同一个 canonical texture 同时解释所有相机，必然会平均。
必须允许模型表达“这些差异不是 canonical texture 本身”，
同时又不能变成记相机。
```

验收：

```text
相对 current-code v183a baseline 和 v179c quick:
  foreground LPIPS 必须下降；
  contour 不恶化；
  c21/c22/c23 held-out view 不能崩；
  residual 可视化必须低幅、局部、可解释。
```

### 大修路线 C：robust multi-view teacher-student，而不是平均所有视角

目标：

```text
不要让低质量/错位/偏色视角直接平均 shared texture。
先构建可靠视角 teacher，再让 student 学稳定高频。
```

做法：

```text
1. 为每个 camera-frame-region 估计可靠性：
   edge alignment score；
   mask confidence；
   photometric consistency；
   camera quality；
   local sharpness。

2. 生成 region/patch 级 teacher target：
   高可靠视角提供 high-frequency/detail 目标；
   不可靠视角只提供低频/轮廓约束，或降权。

3. student 训练：
   shared canonical base 学 consensus；
   HF/detail branch 学 teacher 高频；
   不让 outlier view 的高频梯度直接参与平均。
```

这条路线和 v165/v176-v179 的区别：

```text
v176-v179 是更密地采样所有视角；
路线 C 是先判断哪些视角/patch 可靠，再决定谁能贡献高频。
```

验收：

```text
衣服褶皱、鞋边、裤腿暗部必须比 v179c 更清楚；
肩膀/手臂/hairline 不能因为 teacher 错选而变形；
全图指标可持平，但 foreground / hard contour 必须改善。
```

### 推荐执行顺序

```text
Step 0: 固定 current-code baseline
  以后所有实验先跑：
    v179c render quick
    v183a current no-op validation
    contour diagnostic
  不再直接拿历史 saved best_test_metrics 做唯一 gate。

Step 2: 如果路线 A 有效
  在 corrected substrate 上跑 representation split，而不是再 texture-only continuation。

Step 3: 如果路线 A 无效或收益很小

Step 4: 只有 B/C 出现正信号后

```

### 当前最终判断

截至 v183：

```text
当前清晰度卡住的核心不是：
  训练步数不够；
  texture lr 不对；
  boundary loss 不够；
  单个 camera affine / camera geometry 没调好。

核心是：
```

## 2026-05-09 追加梳理：v198a 之后如何继续提高清晰度

这一节把 `v198a/v199` 之后的下一步拆成三层：先做低风险 ROI probe，再做可靠 teacher/visibility 资产，最后才动 representation。核心原则是：不要再把预算花在同类 late-stage residual、DoG、boundary 权重或 PSNR/SSIM 导向的小修上。

### 一、当前瓶颈的重新表述

`v198a` 已经把 boundary/substrate 这类显式问题收住了一部分，`v199a-e` 则证明下面这些改法都没有真正越过当前清晰度上限：

```text
1. texture-only polish / stable detail / DoG；
2. geometry 稳定后再加小 view-conflict residual；
3. micro camera / pose / boundary / detail joint fine-tune；
4. detail + view-conflict + fill 的组合；
5. 继续只调 LPIPS、patch perceptual、boundary、reliable-view 权重。
```

因此剩余 gap 更像是：

```text
shared canonical texture 承担了过多互相冲突的高频；
现有 residual 没有可靠的局部 owner、visibility gate 和 teacher；
parser/mask/boundary 只能告诉模型“哪里重要”，不能告诉模型“哪个高频是真的”；
late-stage continuation 改动太局部，只能修像素和边界，改不了高频承载方式。
```

后续实验必须区分两件事：

```text
ROI 更准：parser 只负责把 face / arm / shoulder / cloth 区域框准；
高频 teacher 更准：必须知道某个局部细节来自哪个可靠视角，什么时候该学，什么时候不该学。
```

如果没有第二件事，单纯把 detail loss 放大，很容易继续得到 `v199c` 那种 PSNR/SSIM 好一点、LPIPS 和观感反而更软的结果。

### 二、短期：v200 parser-as-ROI-only safe probe

第一步不进入正式 Stage B，不启用 semantic binding，不启用 compact semantic，不启用 soft matte。只把 parser 当成更准的局部 ROI 提供器。

启动前检查：

```text

当前建议路径仍按历史配置检查：
  data/parsers_from_hulk_multiview
或显式指定已有 Hulk parser 输出目录。

如果 parser_root 不存在，先补齐/软链/重新生成 parser labels；
不要在 parser 缺失时直接跑 parser-only，否则会退回空 ROI 或 fallback，实验结论会变脏。
```

建议第一版命名：

```text

```

配置约束：


```text
parser_only 可以验证纯 parser ROI，但如果 parser 缺帧、错类或边界偏移，会把训练信号打空；
```

### 三、中期：先构造 reliable local teacher / visibility confidence，再训练

`v199b` 说明“给 view-conflict 一个小残差出口”并不够。没有可靠 teacher 时，view residual 只会变成受限颜色扰动，而不是稳定高频来源。

下一步应先做 analysis-only 资产，不要直接开训练：

```text
v201a_build_local_teacher_confidence
```

输入：

```text
v198a render；
内部 GT；
foreground mask；
parser ROI；
camera/view metadata；
现有 Gaussian projection / visibility_filter；
局部 contour diagnostics。
```

每个 frame / camera / region 计算：

```text
local photometric error；
local LPIPS 或 patch perceptual proxy；
DoG/Laplacian 高频强度；
boundary distance / mask margin；
parser class consistency；
view angle / projected visibility；
同帧多视角一致性或冲突程度。
```

形成一个局部置信度：

```text
confidence =
  visibility
  * parser_consistency
  * boundary_margin
  * local_alignment_quality
  * high_frequency_reliability
```

teacher 选择规则：

```text
同一局部不要所有视角等权平均；
只选 top-1/top-2 reliable views 作为 teacher；
低置信区域宁可不加 detail teacher，也不要强行监督；
face、肩口、上臂、衣物纹理边界分别统计 coverage；
如果某一区域 reliable coverage 太低，不要在该区域开强 detail loss。
```

analysis-only 的验收：

```text
能输出 per-region coverage 表；
能输出可靠/不可靠区域 heatmap；
能在 v198a_vs_candidate montage 上解释哪些区域是多视角冲突，哪些区域只是 ROI 粗；
至少 face / shoulder_arm / upper cloth 中有一个区域具备足够 reliable coverage，才进入训练。
```

训练版才考虑：

```text
v201b_confidence_gated_detail_teacher
```

训练约束：

```text
只在 high-confidence local teacher 区域加 detail/luma/patch loss；
低 confidence 区域保持 v198a 原损失，不强推高频；
teacher loss 必须被 visibility gate 和 region owner gate 同时限制；
仍以 v198a quick render 作为唯一主锚点。
```
